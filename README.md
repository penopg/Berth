# Berth

Терминал, в котором **проект и сессия агента — первоклассные сущности**, а не
случайная вкладка со случайным рабочим каталогом.

Berth — причал: место, где у каждого проекта своя стоянка, к которой можно
вернуться, и всё пришвартованное остаётся на месте.

Ядро терминала — [libghostty-vt](https://github.com/ghostty-org/ghostty):
разбор VT, состояние экрана, рефлоу, скроллбэк, Kitty-протоколы клавиатуры и
графики. Окно, ввод и отрисовка — raylib. Всё остальное пишем сами.

> Статус: рабочий прототип, которым автор пользуется каждый день. Есть
> вкладки-проекты с панелью и группами, страница проекта с журналом работы,
> задачами и сводкой, сессии Claude Code как сущность (одна на проект,
> состояние и контекст в панели), лимиты в верхней полосе, темы и настройки.
> Что дальше — в [ROADMAP.md](ROADMAP.md), как устроено — в [CLAUDE.md](CLAUDE.md).

## Зачем

Ни один из терминалов, что были под рукой, не давал нужного сочетания:

|                                   | Warp | WezTerm | iTerm2 |
|-----------------------------------|:----:|:-------:|:------:|
| вертикальные вкладки слева        |  да  |   нет   |   да   |
| разные темы у окон одновременно   | нет  |   да    |   да   |
| иконки вкладок                    | нет  |   да    |  нет   |
| заголовок вкладки не затирается   | нет  |   да    |   да   |

## Сборка

macOS. Нужны `zig` (для libghostty-vt), `git`, `curl`, `make`, `python3`.

```sh
./build.sh          # первый запуск собирает зависимости, это несколько минут
./build/berth
./build/berth ~/work/api ~/personal/blog   # вкладка на каталог

./bundle.sh                        # собрать Berth.app с иконкой
cp -R build/Berth.app /Applications/
```

Приложение из бандла запускает оболочку как login shell, поэтому в вкладках
доступен обычный `PATH` — иначе запущенному из Dock приложению не досталось бы
ни `claude`, ни `git`.

## Горячие клавиши

| | |
|---|---|
| `⌘T` / `⌘W` | открыть / закрыть вкладку (новая наследует каталог текущей) |
| `⌘Q` | выйти, погасив все сессии |
| `⌘1`…`⌘9` | вкладка по порядку в панели |
| `⌘⇧[` / `⌘⇧]` | предыдущая / следующая |
| `⌘B` | показать или спрятать панель |
| `⌘R` | перечитать список проектов |
| `⌘K` | почистить контекст агента |
| `⌘+` / `⌘−` / `⌘0` | размер шрифта |
| `⌘V` | вставить из буфера |

Клик по проекту открывает в нём агента; если у проекта есть прошлые сессии,
диалог продолжается сам. ⌥-клик и `⌘T` открывают обычную оболочку.

Раскладка вкладок переживает перезапуск: терминал помнит, что было открыто, и
восстанавливает — вместе с продолжением прошлых диалогов.

## Проекты

Панель показывает список проектов из `~/.claude/warp-tabs/projects.json` —
имя, группу, цвет и тему. Клик по проекту открывает его вкладкой, клик по
открытому переключает. При открытии печатается паспорт проекта: ветка git,
последние сессии Claude, статус из `CLAUDE.md`.

Тема берётся у проекта, а не у приложения: рабочие проекты могут быть тёмными,
а личные светлыми — одновременно, в одном окне.

Файл списка правится снаружи; терминал замечает правку сам, перезапуск не нужен.
Вкладки, открытые не из списка (аргументом или по ⌘T), группируются по
родительскому каталогу и живут в разделе «прочее».

Официальный путь сборки через CMake здесь не используется: `build.zig` у ghostty
безусловно собирает XCFramework для iOS, а это требует полного Xcode, хотя
документация обещает Command Line Tools. `zig build lib-vt` при этом проходит
до конца, поэтому `build.sh` собирает зависимости адресно и линкует напрямую.

## Устройство

```
src/
  app.c        окно, главный цикл, горячие клавиши
  session.c/h  вкладка: проект, агент, метрики — поверх Term
  agent.c/h    профили агентов (оболочка, Claude Code) — данными, не кодом
  projects.c/h список проектов из projects.json
  json.c/h     разбор JSON под этот формат, без внешних зависимостей
  layout.c/h   раскладка и попадание мыши: панель, разделитель, терминал
  ui.c/h       отрисовка панели
  theme.h      цвета интерфейса
  term.c/h     сессия терминала: дочерний процесс + состояние libghostty
  pty.c/h      псевдотерминал: запуск оболочки, чтение и запись
  input.c/h    клавиатура, мышь, скроллбар
  render.c/h   отрисовка сетки, курсора, картинок Kitty
  font.c/h     атлас глифов и метрики ячейки
  utf8.c/h     кодирование кодпоинтов
```

Слои разделены намеренно. `Term` знает про VT и дочерний процесс и ничего не
знает про проекты и агентов; `Session` — наоборот. Всё, что появится дальше
(процент контекста, состояние агента, индикаторы), оседает в `Session` и не
протекает в код терминала. Раскладка живёт отдельно от отрисовки: клик
проверяется по тем же прямоугольникам, по которым рисуется панель.
