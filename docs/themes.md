# Темы и стили: проект

Статус: проект для обсуждения (2026-09-06). Задачи заводятся после.

## Как сейчас, и что в этом плохо

**Тема — 15 цветов в структуре `Theme`, четыре набора вшиты в `theme.h`.**
Имя темы приходит из `projects.json` (это имена тем Warp: «Tokyo Night»,
«Gruvbox Light», «Catppuccin Mocha»), незнакомое имя даёт тёмную по
умолчанию. Коллега, который хочет свою тему, должен править C и
пересобирать.

**Окно красится темой активной вкладки.** Каждый кадр `app.theme` берётся
у активной вкладки, и панель, полоса, страницы перекрашиваются при
переключении. Это и есть «волшебство»: светлое и тёмное решает не человек и
не система, а то, какой проект сейчас выбран. Задумка была ценная — личные
проекты видно с первого взгляда, — но цена высокая: панель, которую
читаешь постоянно, скачет между светлой и тёмной.

**Терминал получает от темы только фон и текст.** Шестнадцать цветов ANSI
остаются палитрой libghostty по умолчанию: в Gruvbox Light терминал рисует
чужие красные и синие, и `ls` выглядит не как в Warp с той же темой.

**Цвета разбросаны.** Курсор и выделение в `render.c`, тень карточки в
`page.c`, цвет проекта без имени в `projects.c`, затемнение под редактором
в `app.c`, прозрачности в `ui.c`. Имена цветов проектов («blue») из
`projects.json` переводятся своей таблицей в `projects.c`, никак не
связанной с темой.

**Роли размыты.** `row_text_dim` используется 64 раза для всего
второстепенного: подписи, описания, заголовки разделов, состояния.
`badge_attention` — это и «агент зовёт», и «проверить», и янтарный порог
контекста. `progress_fill` — акцент вообще. Для страницы (кнопки,
карточки, редактор, тени) ролей нет вовсе, и она подбирает их из панельных.

**Размеров и отступов это тоже касается.** `c.y + 6`, `26`, `time_w`,
`ROW_MARKER 10` — числа по коду. Это второй слой той же проблемы; в этом
проекте он только зафиксирован, в работу идёт после цветов.

## Цели

- **Понятно.** Одно место, где тема определена; роли названы по смыслу
  («текст приглушённый», «опасность»), а не по месту («row_text_dim»).
- **Контролируемо.** Кто решает, светло или темно, — записано одним
  правилом с известным порядком: настройка → система → проект.
- **Логично.** Цвета интерфейса выводятся из палитры терминала, а не
  подбираются руками по пятнадцать штук на тему.
- **Кастомизируемо.** Тема — файл. Коллега кладёт файл в папку, и она
  появляется в настройках. Без C, без сборки.

## Три слоя

### 1. Палитра терминала — файл в формате Ghostty

Формат уже есть, и он лучше своего: строки `ключ = значение`,
`palette = N=#rrggbb` для шестнадцати цветов, `background`, `foreground`,
`cursor-color`, `cursor-text`, `selection-background`,
`selection-foreground`. У Ghostty 438 готовых тем в этом формате
(`/Applications/Ghostty.app/Contents/Resources/ghostty/themes/`), среди
них все три, что стоят в `projects.json`. Разбор строки палитры даёт сам
libghostty (`ghostty_color_parse_palette_entry`), остальные ключи — шесть
строк своего разбора. Палитра ставится терминалу целиком
(`GHOSTTY_TERMINAL_OPT_COLOR_PALETTE`), OSC-переопределения приложений
при этом сохраняются — это libghostty обещает в заголовке.

Где лежат темы:

    <бинарь>                          шесть встроенных, как скиллы берта:
                                      berth dark, berth light, Tokyo Night,
                                      Gruvbox Light, Catppuccin Mocha,
                                      Catppuccin Latte
    ~/.config/berth/themes/<имя>      свои; одноимённая перекрывает встроенную

Папка перечитывается по mtime тем же опросом, что настройки. Файл из
Ghostty копируется как есть — это и есть «кастомизация для коллег».

### 2. Роли интерфейса — выводятся из палитры

Интерфейсу нужно около двадцати цветов, и почти все они — смесь фона и
текста в разной пропорции либо один из шестнадцати цветов палитры.
Правило вывода одно на все темы, поэтому любая тема Ghostty даёт
согласованный интерфейс без единого цвета «для берта».

    роль            откуда                              где используется
    bg              background                          фон окна и терминала
    surface         mix(bg, fg, 5%)                     панель, полоса, карточка
    surface_hover   mix(bg, fg, 10%)                    строка под курсором
    surface_active  mix(bg, fg, 16%)                    активная строка, кнопка
    border          mix(bg, fg, 15%)                    рамки, разделитель, черта
    border_strong   mix(bg, fg, 30%)                    рамка редактора
    text            foreground                          основной текст
    text_dim        mix(fg, bg, 40%)                    описания, подписи
    text_faint      mix(fg, bg, 60%)                    заголовки разделов, время
    accent          palette[4] (синий) или [12]         активная вкладка, кнопка
                                                        действия, шкала
    busy            accent                              маркер «работает»
    warn            palette[3] (жёлтый)                 «зовёт», «проверить»,
                                                        порог ctx_warn
    danger          palette[1] (красный)                «умер», ctx_crit, ошибка
    ok              palette[2] (зелёный)                сделанная задача
    cursor          cursor-color                        курсор терминала
    selection_bg/fg selection-*                         выделение (когда будет)
    shadow          чёрный, альфа по константе          тень плашки и карточки
    dim             чёрный, альфа по константе          затемнение под редактором

Светлая тема или тёмная — по яркости `background` (относительная
светимость выше 0.5), а не по имени. От этого зависит только направление
смесей и то, из какой половины палитры брать яркие цвета: в светлой теме
`accent` из [4], в тёмной — из [12].

Если вывод для какой-то темы даёт плохой цвет, файл темы может
переопределить любую роль строкой с префиксом: `berth.accent = #…`.
Ghostty такие строки не знает, но и не читает наши файлы. Переопределения
— исключение, а не способ описать тему.

Проверка формальная: тест считает контраст (по WCAG) `text/bg ≥ 4.5`,
`text_dim/bg ≥ 3`, `accent/surface ≥ 3` для каждой встроенной темы.
Сейчас такого критерия нет, и «читается ли приглушённый на светлой»
решают глаза.

### 3. Правило выбора: кто решает

Настройки:

    appearance   = system | light | dark   # откуда светло/темно
    theme_dark   = Tokyo Night             # тема окна в тёмном режиме
    theme_light  = Gruvbox Light           # …в светлом
    project_theme = terminal | window | off

`appearance = system` читает вид macOS (`NSApp.effectiveAppearance`,
подписка на смену — окно перекрашивается вслед за системой). Окно —
панель, полоса, страницы — красится темой режима.

`project_theme` отвечает за тему проекта из `projects.json`:

- `terminal` (по умолчанию): тема проекта красит **только область
  терминала** этой вкладки — палитру, фон, текст. Панель стоит на месте,
  а личный проект по-прежнему виден с первого взгляда: его терминал
  светлый.
- `window`: нынешнее поведение — окно целиком следует активной вкладке.
  Для тех, кому оно нравится.
- `off`: тема проекта игнорируется, у всех терминалов тема окна.

Имена тем Warp переводятся в имена Ghostty таблицей псевдонимов
(«Tokyo Night» → `TokyoNight`, «Gruvbox Light» → `Gruvbox Light`,
«Catppuccin Mocha» → `Catppuccin Mocha`), незнакомое имя — тема окна, с
подписью на странице проекта, а не молча.

Цвет проекта («blue» в `projects.json`) переводится в цвет палитры
текущей темы (`palette[4]`), а не в свою таблицу: тогда черта группы и
плашка совпадают с терминалом.

## Что меняется в коде

- `theme.h` перестаёт быть таблицей и становится модулем `theme.c`:
  `theme_load_all()` (встроенные + папка), `theme_by_name()`,
  `theme_derive()` (палитра → роли), `theme_is_dark()`. Структура:
  `TermColors term` (bg, fg, cursor, selection, palette[16]),
  `UiColors ui` (роли выше), `bool dark`, `name`.
- Все `th->row_text_dim` и прочие переименовываются в роли. Это
  механическая замена ~150 мест, но с разбором: часть `row_text_dim`
  станет `text_faint`, часть `badge_attention` — `warn`.
- Литералы уходят: курсор и выделение в `render.c` из `term`, тени и
  затемнение из `shadow`/`dim`, `projects.c` теряет таблицу цветов.
- `app.theme` остаётся «темой окна», но выбирается правилом, а не активной
  вкладкой. У `Session` остаётся ссылка на тему проекта — для терминала.
- `term_set_default_colors` расширяется до палитры и курсора.
- Экран настроек: вид (система/светлый/тёмный), две темы списком с
  образцом (полоска из восьми цветов палитры), «Открыть папку тем».

## Что не делаем

- Свой формат темы и редактор тем в окне. Файл Ghostty и текстовый
  редактор покрывают всё.
- Автоматическую конвертацию тем Warp: их три, псевдонимов хватает.
- Размеры и отступы. Второй слой, отдельный проект после цветов: `Style`
  с `pad`, `gap`, `row_h`, и замена чисел в `page.c`/`layout.h`.

## Предлагаемые задачи (после обсуждения)

1. **Формат темы и загрузчик.** Разбор файла Ghostty плюс `berth.*`,
   шесть встроенных тем в бинаре, папка `~/.config/berth/themes`,
   перечитывание по mtime, псевдонимы имён Warp. Тест: разбор трёх
   файлов из Ghostty.app даёт ожидаемые цвета.
2. **Роли интерфейса.** `UiColors`, вывод из палитры, тест контраста;
   замена всех обращений к старым полям; литералы убраны. Вид окна не
   должен измениться для четырёх нынешних тем — сверка глазами.
3. **Палитра терминала.** Шестнадцать цветов, курсор и выделение
   ставятся терминалу; `ls --color` в Gruvbox Light выглядит как в Warp.
4. **Правило выбора.** `appearance`, `theme_dark/light`, `project_theme`,
   системный вид с подпиской, экран настроек с образцами. Окно больше не
   скачет при переключении вкладок, если `project_theme = terminal`.
5. **Размеры и отступы** — отдельно, после.

## Сценарии, которые это закрывает

Для человека за окном:

1. **Коллега приносит свою тему.** Копирует файл Ghostty в
   `~/.config/berth/themes`, выбирает в настройках. Сегодня — правка C и
   пересборка.
2. **Вечером темно, днём светло.** macOS переключает вид, берт следует.
   Сегодня берт про систему не знает.
3. **Переключение проектов не бьёт по глазам.** Панель и полоса на месте,
   где ты — видно по терминалу. Сегодня перекрашивается всё окно.
4. **Вывод в терминале как в Warp с той же темой.** Шестнадцать цветов
   ANSI из темы. Сегодня — палитра по умолчанию поверх любой темы.
5. **Плохо видно — поправил одну строку** (`berth.text_dim = #…`). Плюс
   тест контраста для встроенных тем.

Для того, кто пишет берт:

6. **Новый элемент знает, какой цвет взять** — роль по смыслу, а не одно
   из пятнадцати полей.
7. **Новая тема не требует подбирать пятнадцать цветов** — одно правило
   вывода.
8. **Тема с ошибкой видна** подписью на странице проекта, а не молча
   даёт тёмную.

Не закрывает: тему на группу-папку (отклонено), размеры и отступы
(следующий слой), редактор тем в окне (файл и текстовый редактор).

## Решения (2026-09-06)

1. Тема проекта красит терминал; панель и полоса — темой окна.
2. Формат Ghostty.
3. Проекты вне `projects.json` тему не объявляют.

   проекта свой) или `window` (как сейчас)? Предлагаю `terminal`.
2. Формат Ghostty вместо своего — возражений нет? Аргумент: 438 готовых

3. Где проект объявляет тему, когда он не из `projects.json`
