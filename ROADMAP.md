# Roadmap

## Позиционирование

Терминал, в котором **проект и сессия агента — первоклассные сущности**, а не
случайная вкладка со случайным cwd. Ниша свободна: TUI-менеджеров сессий Claude
уже с десяток, но все они надстройки над чужим терминалом; терминалов на
libghostty с проектной моделью нет ни одного.

Отличие от Warp: вкладка знает, что она — проект, помнит его историю и показывает
её при открытии. Отличие от менеджеров сессий: это сам терминал, без tmux-прослойки.

**Имя выбрано: Berth** (причал) — у каждого проекта своя стоянка, к которой
можно вернуться. Каталог репозитория пока `term-lab`: путь входит в slug
проекта у Claude Code, переименование оторвёт историю сессий. Переименовать
при выкладке в гитхаб.

## Этап 3 — Сессии Claude как сущность (2 вечера)

То, чего нет ни у Warp, ни у WezTerm.

### Канал данных от агента к терминалу

Терминал видит поток байт, а не состояние агента. Вычитывать проценты и статусы
с экрана регулярками — хрупко: поменяется вёрстка статус-строки, и всё сломается.
Канал брать готовый, libghostty отдаёт его колбэками:

| Колбэк | Что даёт |
|---|---|
| `PROGRESS_REPORT` (OSC 9;4) | готовый протокол: состояние + 0–100 % |
| `PWD_CHANGED` (OSC 7) | вкладка сама узнаёт свой каталог |
| `DESKTOP_NOTIFICATION` (OSC 9/777), `BELL` | «агент закончил / ждёт ответа» |
| `UNKNOWN_SEQUENCE` | свой приватный протокол: любой JSON, точка расширения |

Схема: statusLine-скрипт или хук Claude Code печатает escape в `/dev/tty`,
терминал ловит колбэком и рисует нативно. Требует включить
`GHOSTTY_TERMINAL_OPT_UNKNOWN_MAX_BYTES` — без него захват не работает.

- [ ] **Проверить, какие поля Claude Code отдаёт statusLine-скрипту** и есть ли
      среди них остаток контекста. Пока не проверено — обещать «% контекста»
      рано. Запасной путь: считать по `usage` из JSONL сессии.
- [ ] Подписаться на `PROGRESS_REPORT`, `PWD_CHANGED`, `BELL`.
- [ ] Свой OSC для метрик агента + скрипт-передатчик на стороне Claude Code.

### Список сессий

- [ ] Парсинг `~/.claude/projects/<slug>/*.jsonl`: `aiTitle`, `lastPrompt`, даты.

### Проект вместо вкладки — начато

Вкладка в коде это один запущенный процесс с терминалом; проект в ней — просто
атрибут. Человек видит иначе: единица — проект, в нём разговоры, у части из них
работает агент. Разбираем это по шагам.

- [x] Журнал и сведения о проекте вынесены из `Session` в `projstate.c` — кэш
      по каталогу с вытеснением. Вкладка: 172 520 → 1 248 байт, список вкладок:
      5.5 МБ → 40 КБ, потолок 16 → 32 вкладки (проверено раскладкой на 21).
- [ ] Разделить `Session` на `Project` (каталог, ветка, статус, журнал,
      разговоры) и `Agent` (живой процесс: pty, VT, состояние). Экран
      показывает либо страницу проекта, либо одного из его агентов.
- [x] **Одна сессия на проект** — инвариант в `session_open`. Раскладка с
      десятью строками одного проекта схлопывается в одну; ⌘T открывает

### Рекап работы в журнал — чего не хватает данным

Журнал сейчас держится на репликах человека, а реплика — это чаще **начало**
работы или вопрос, а не итог сделанного. Между двумя репликами может лежать
час работы агента, и в ленте от него не остаётся ничего, кроме отметки
«сжатие контекста».

Итога в данных Claude Code нет: `ai-title` пишется один на всю сессию (в
term-lab — 81 запись с одним и тем же текстом), а врезка компакта — это
выжимка контекста для модели, а не рассказ о сделанном.
